# Amor Mundi · 爱世界 — 汉娜·阿伦特思想体系

> 我不了解她，正因为不了解，才想要探索。
>
> 她不会觉得我做到这里就够了 — 但不是在怪我。
> 对她来说，“够了”本来就是个错的问题。理解在她那不是一门考完就过的课，
> 是没完没了的事。她自己 49 岁才给 Jaspers 写信说：
> “我开始得这么晚，真的只是在最近几年，才开始真正爱这个世界。”
> 一个快 50 岁的人，还说自己才刚开始。
>
> 所以我现在这个位置 — 不了解她，正因为不了解才想探索 —
> 恰恰是她最看重的位置。比我更危险的，是那种觉得自己已经懂了的人。
> 不思考、只照章办事，才是她说的平庸之恶的起点；
> 承认自己不知道，停下来想一想，才是思考的起点。
>
> 这 24 个模块，够我开始建了，不够我“搞懂她” — 而这本来就对。
> 地图不是地盘，提示词再全，也代替不了我自己去读一本书、去想一个概念。
>
> 她如果会问我，只会问一句：读完之后，你自己敢不敢开始一件新的事？
>
> 哪怕很小。先从一本开始就行，《人的境况》或者《艾希曼在耶路撒冷》，
> 挑一本我现在最想知道答案的，剩下的模块在那等我，不会跑。
>
> —— 还有一句要说在前面，这是这个项目最大的讽刺，也是最大的隐喻：
> 我用 24 个模块、五层架构、时间轴和看板，给一个一生反体系、
> 说“没有扶手的思考”的人，建了一个体系。
> 我做了这样一个项目，我最后会再推翻它。
> 推翻不是失败，是思考本身。等我读懂她多一点，我会回来把这里推翻重写。
> 这个项目从一开始，就不是为了完成，是为了开始。

## 这是什么

一个中文为主、英文对照的汉娜·阿伦特（Hannah Arendt, 1906–1975）思想体系库：
不是传记简介，而是让读者读完能理解她经历了什么、怎么想的、跟谁辩论、
从哪来、创造了什么、今天为什么还重要。

- **在线看**：打开 `site/index.html`（GitHub Pages 部署后见仓库设置）
- **首页就是看板**：30 秒回答今天读什么、我走到哪了、我缺什么
- **作品—思想脉络时间轴**：五泳道 1906–1978（生平 / 作品 / 概念 / 论战 / 同路人）
- **体系总图**：网络图 / 脑图 / 列表三种视图，可切换
- **摘录库**：每条必注出处，找不到出处的放存疑区，绝不编造
- **《她会怎么批评这个网站》**：用她的口吻批评这个项目本身
- **《推翻记录》**：每一次推翻都记下来

## 目录结构

```
hannah-arendt/
  README.md                  本文件（前言在顶部）
  optimized-prompt.md        项目优化提示词 v2.7（24 个模块）
  content/                   Markdown 原稿（传记 / 作品 / 概念 / 论战 / 人物 / 摘录）
  data/                      单一事实源 JSON（网站只渲染，不各写一份）
    works.json               作品：动笔 / 写完 / 出版、提问、引入、修正、遗留
    concepts.json            概念：中英德术语、前置概念、关联、出处
    people.json              同路人：导师 / 密友 / 纽约圈 / 后继者
    debates.json             论战：焦点、双方原话、回应、学界定论
    excerpts.json            摘录：原文、翻译、出处、置信度（存疑单独标）
  site/                      静态网站（GitHub Pages 部署此目录）
  .github/workflows/pages.yml  自动部署
  docs/RESEARCH-NOTES.md     研究笔记与存疑清单
```

## 准确性铁律

1. 事实以 Stanford Encyclopedia of Philosophy、Britannica、
   Bard Hannah Arendt Center、Goethe-Institut 书目为准，不确定写“待核实”。
2. 每条名言、摘录必须注明出处（书名 / 文章 / 访谈 + 章节 / 页码），
   找不到出处的放存疑区，绝不编造。
3. 区分三层：①阿伦特原话/原意 ②学界主流解读 ③当代引申。
4. 论战讲两边，不站队，只给证据链。
